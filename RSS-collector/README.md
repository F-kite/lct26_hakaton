# RSS-коллектор слабых сигналов

Венчурно-медийный слой сбора для кейса Газпромбанк Тех (ЛЦТ 2026).
Собирает TechCrunch, SiliconANGLE, MIT News, McKinsey, НИУ ВШЭ.

## Зачем запускать прямо сейчас

RSS-лента отдаёт только последние ~20–50 записей и **не имеет исторической глубины**.
Признак «тренд упоминаний» — один из двух, по которым размечен ваш датасет 100 сигналов —
без истории не посчитать. Каждый день простоя = день недобранных данных к демо.

Коллектор ни от чего не зависит: запускается до того, как будет готова модель,
парсер патентов и интерфейс.

## Запуск

```bash
docker compose up -d          # Postgres + коллектор в режиме loop каждые 30 мин
docker compose logs -f collector
```

Локально, без Docker:

```bash
pip install -r requirements.txt
export DATABASE_URL="postgresql+psycopg://signals:signals@localhost:5432/signals"

python -m collector.main init                  # создать таблицы
python -m collector.main discover hse          # найти URL ленты ВШЭ
python -m collector.main collect               # однократный сбор
python -m collector.main loop --interval 1800  # непрерывно
python -m collector.main stats                 # что накопилось
```

`stats` показывает по каждой ленте число записей, глубину истории и счётчик сбоев —
это главная метрика готовности к демо.

## Что нужно сделать перед первым прогоном

У ВШЭ `url=None`: точный адрес ленты не подтверждён. Запустите
`python -m collector.main discover hse`, впишите найденный URL в `collector/feeds.py`.
Если лент не найдено — источник уходит в HTML-парсер, RSS у него нет.

Тот же `discover` пригодится позже: когда сайт сменит адрес фида, чинится он,
а не константа в коде.

## Заложенные решения

**Отказоустойчивость** — отдельный критерий оценки (п. 8.2 ТЗ). Реализовано:

| Механизм | Где |
|---|---|
| Изоляция лент — падение одной не роняет прогон | `core.collect_all` |
| Ретраи с экспоненциальной задержкой на 429/5xx, учёт `Retry-After` | `core._fetch` |
| Условный GET по `ETag` / `Last-Modified` | `core.collect_one` |
| Дедупликация по `UNIQUE(url_hash)` на уровне БД, не в памяти | `db.FeedItem` |
| Счётчик `consecutive_failures` и `last_error` на источнике | `db.Source` |

**Соблюдение Terms.** У TechCrunch отдельные RSS Terms: атрибуция, ссылка на оригинал,
контент не изменять, полный текст не копировать. Поэтому коллектор сохраняет только то,
что отдаёт лента — заголовок, summary, ссылку, дату, автора. Полные статьи не выкачиваются
нигде. Флаг `store_summary=False` в `feeds.py` отключает сохранение текста для источника,
если его условия окажутся жёстче.

**Поля под требования ТЗ.** ТЗ требует показывать для каждого источника наименование,
ссылку, дату публикации, тип источника, язык оригинала и уровень доверенности. Всё это
пишется в `feed_items` сразу при сборе, денормализованно — чтобы выдача строилась одним
запросом без джойнов.

`sponsored` и `is_translated` заполняются не здесь: первый — классификатором рекламных
материалов (актуально для SiliconANGLE), второй — модулем перевода зарубежных источников.
Коллектор оставляет их `False`.

## Структура

```
collector/
  feeds.py      реестр лент + метаданные доверия
  db.py         SQLAlchemy-модели Source и FeedItem
  discover.py   автодискавери лент (link rel=alternate + типовые пути)
  core.py       сбор, ретраи, дедупликация
  main.py       CLI
```
