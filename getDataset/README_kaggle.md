# Скачивание датасета arXiv с Kaggle

## Что это за файл

Датасет `Cornell-University/arxiv` — метаданные всех статей arXiv: заголовок,
аннотация, категории, даты версий, авторы, DOI. Самих PDF там нет, только
описания — это и нужно для анализа трендов.

Скачивается как **zip-архив (~1,5 ГБ)**, внутри один файл
`arxiv-metadata-oai-snapshot.json` **на 4–5 ГБ**.

Важно: это не обычный JSON, а **JSON Lines** — каждая строка файла является
самостоятельным JSON-объектом. Открывать его через `json.load()` нельзя:
питон попытается разобрать 5 ГБ целиком и съест всю память. Читать надо
построчно, что скрипт и делает.

## Подготовка (один раз)

```bash
pip install kagglehub pandas pyarrow
python prepare_arxiv.py --login
```

`--login` спросит имя пользователя Kaggle и API-токен и сохранит их.
Токен берётся так: kaggle.com → **Settings → API → Create New Token**,
скачается файл `kaggle.json`, внутри него нужные `username` и `key`.

Альтернатива без интерактива — переменные окружения:

```bash
export KAGGLE_USERNAME=твой_логин
export KAGGLE_KEY=твой_ключ
```

Ещё вариант — положить скачанный `kaggle.json` в `~/.kaggle/`
и выставить `chmod 600`. kagglehub подхватит его сам.

**Обязательный шаг:** зайти на
[страницу датасета](https://www.kaggle.com/datasets/Cornell-University/arxiv)
и один раз нажать кнопку скачивания в браузере. Kaggle требует явно принять
условия использования, иначе API вернёт ошибку доступа.

## Запуск

```bash
# сначала посмотреть, как реально устроена запись
python prepare_arxiv.py --peek

# отладочный прогон на 50 тысячах записей — пара минут
python prepare_arxiv.py --limit 50000

# полный прогон — 15-40 минут в зависимости от диска
python prepare_arxiv.py
```

Результат складывается в `data/02_clean/` как набор parquet-файлов.
Читается одной строкой:

```python
import pandas as pd
df = pd.read_parquet("data/02_clean")
```

## Структура папок после запуска

```
data/
  01_raw/
    arxiv-metadata-oai-snapshot.json   ← распакованный JSON Lines
  02_clean/
    part_0000.parquet                  ← готовые данные
    part_0001.parquet
    ...
  02_clean_limit50000/                 ← отдельная папка для отладочных прогонов
```

## Про kagglehub и кеш

По умолчанию `kagglehub.dataset_download()` кладёт файлы в `~/.cache/kagglehub/`
и возвращает путь туда. Для пятигигабайтного датасета это неудобно: данные
уезжают в домашний раздел, и в проекте их не видно.

Поэтому в скрипте передаётся `output_dir` — файлы падают прямо в `data/01_raw/`.
Если хочется оставить кеш, но перенести его в другое место, есть переменная
окружения `KAGGLEHUB_CACHE`.

Полезно знать: у `dataset_download` есть аргумент `path` — он качает
**один конкретный файл** из датасета, а не всё целиком. Для arXiv разницы
почти нет (там один большой файл), но на других датасетах это экономит часы.

## Чего делать не надо

У kagglehub есть удобная функция `dataset_load(KaggleDatasetAdapter.PANDAS, ...)`,
которая грузит датасет сразу в DataFrame. **На этом датасете её использовать
нельзя** — она попытается поднять все 5 ГБ в память одним куском. Для больших
файлов только построчное чтение.

## Повторный запуск

Каждый шаг проверяет, сделан ли он уже: скачанный файл не перекачивается,
готовый parquet не пересобирается.

Чтобы пересобрать шаг — удали его результат:

```bash
rm -rf data/02_clean      # пересобрать parquet заново
```

## Если что-то пошло не так

**Ошибка доступа при скачивании** — не принято соглашение об использовании
датасета. Зайти на страницу датасета в браузере и нажать Download.

**Не находит доступы** — запустить `python prepare_arxiv.py --login`
или выставить `KAGGLE_USERNAME` и `KAGGLE_KEY`.

**Кончилось место на диске** — суммарно нужно около 12 ГБ: 1,5 на архив,
5 на распакованный JSON, остальное на parquet. После успешной конвертации
исходный json можно удалить.

**Скрипт долго висит на конвертации** — это нормально, 5 ГБ читаются
построчно. Прогресс виден по появляющимся part-файлам, каждый по
200 тысяч записей.

## Почему parquet, а не CSV

Parquet хранит данные по колонкам и сжимает их. Читать «только год и категорию
из трёх миллионов строк» он будет за секунды, не загружая в память аннотации.
Для тех подсчётов, которые нужны в задаче, это разница между секундой и минутой
на каждом запросе.
