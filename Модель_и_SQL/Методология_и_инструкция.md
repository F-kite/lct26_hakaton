## 1. Что именно определяет модель

На входе — **английский текст конкретной публикации о технологии**. На выходе — один из трёх классов:

| Класс | Простое правило разметки | Условный пример |
|---|---|---|
| Слабый сигнал | Есть конкретное новое техническое решение, исследование, прототип, пилот или раннее внедрение | Новый способ обучения робота проверили в ограниченном эксперименте |
| Зрелая технология | Основной предмет статьи — уже используемое решение и его обычная эксплуатация | Компания описывает работу существующей облачной платформы у пользователей |
| Шум | Материал не даёт нужного технологического сигнала | Финансовый отчёт, назначение руководителя, судебный спор |

Один сайт может публиковать все три вида материалов. Класс относится к содержанию публикации, а не к сайту целиком. В смешанном материале разметка относится к основному предмету статьи.

Новый раунд инвестиций сам по себе не доказывает новизну технологии. Слово «ИИ» тоже не делает новость слабым сигналом. Для положительных примеров здесь принят ваш эталон: технологии из исходного Excel считаются слабыми сигналами.

### Почему нельзя было просто обучиться на исходных 100 строках

Во всех 100 строках был один ответ: «слабый сигнал». Если показывать алгоритму только такие примеры, ему неоткуда узнать различие между зрелой технологией и шумом. В каталоге источников и большой ленте правильных ответов этих двух классов тоже нет. Поле `low` означает доверие к источнику, а не «шум».

Поэтому к положительным примерам добавлены **реальные публикации двух других классов**. Это необходимые обучающие ответы, а не придуманные значения патентов или просмотров.

## 3. Как устроена модель — без сложной математики

1. Берём заголовок, описание и очищенный текст прочитанной статьи. В подготовке использовано до 14 000 символов основного текста; удалены URL и часть повторяющихся служебных вставок.
2. Считаем слова. Порядок слов в этой модели не используется.
3. TF-IDF превращает эти частоты в числа: очень распространённые слова получают меньший вес.
4. Логистическая регрессия учится связывать полученные числа с тремя классами.
5. Для новой статьи те же действия выполняются внутри загруженной модели.

Выбрана одна простая схема: **TF-IDF → логистическая регрессия**. Для неё нужны только `pandas` и `scikit-learn`. `pickle` для сохранения входит в Python. Дополнительные модели перевода, нейросетевые сервисы или ключи доступа не используются.

Модель получает **только слова публикации**. Номер Excel, правильный класс, направление, стадия, исходный балл и пояснение эксперта не передаются как признаки. Правильный класс используется в `fit` как ответ для обучения, а не как часть входного текста.

В CSV слова каждой статьи расположены по алфавиту, с сохранением повторов. Например, «robot pilot robot» становится «pilot robot robot». Частоты не меняются. Проверено: для всех 248 записей обычный подготовленный текст и такой список слов дают одинаковые признаки и оценки модели. Это позволяет воспроизвести обучение без включения полных текстов чужих статей в архив. Новую статью сортировать по словам не требуется.

Модель распознаёт статистические связи, а не устанавливает техническую новизну как эксперт. Например, в этих данных со слабыми сигналами связаны слова `funding`, `startup`, `agents`, а с шумом — `earnings`, `revenue`, `lawsuit`. Это объясняет и полезность модели, и возможные ошибки: новость о выручке ИИ-компании иногда похожа на технологический анонс.

### Как получен топ-15

Из контрольных публикаций взяты ответы «слабый сигнал». Они отсортированы по внутренней оценке этого класса. Из каждой заранее определённой группы оставлена одна публикация; затем выбраны первые 15 групп. Только после этого выполнена сверка с номерами исходного Excel.

**Получено 15 разных совпадений из 15 — 100% на этой проверке.** Номера: 81, 75, 37, 64, 77, 74, 97, 48, 23, 5, 86, 44, 3, 98, 25. Названия и ссылки находятся в `Результаты/Топ15.csv`.

Ваш порог «не менее 80%» — это минимум 12 совпадений из 15. Для строго большего результата нужны минимум 13. Внутренняя оценка модели, например 0.65, **не является этим показателем** и не доказывает достоверность источника на 65%. Фильтр «оценка больше 0.80» здесь не нужен.

Дополнительно метод проверен на пяти разбиениях: каждый раз заново обучалась та же схема с теми же настройками, целые группы оставлялись для проверки. Совпадения в топ-15: **15, 15, 14, 15, 15**. Настройки и переданный файл модели после этого не менялись. Полные числа — в `Результаты/Устойчивость.csv`.

### Что эти числа подтверждают

Это внутренняя проверка на подготовленной разметке. Основная контрольная выборка уже использовалась при разработке предыдущей версии; она не является новой внешней экспертизой. Разметка двух отрицательных классов не подтверждена организаторами.

Тема проверенного топ-15 — **все шесть направлений вместе**. Группы технологий в проверке известны заранее. Не измерялись точность произвольного интернет-поиска, автоматического выделения новых технологий из страниц и отдельного топ-15 на каждый узкий вопрос. Поэтому переносить 100% на любой новый запрос нельзя.

Все 76 контрольных публикаций англоязычные. Русских обучающих публикаций всего шесть, и все они относятся к шуму. **Эту модель нельзя считать проверенным классификатором русских статей.** Русский поисковый вопрос допустим на уровне приложения, но в эту модель должен поступать английский материал.

## 6. Из чего, вероятно, складываются баллы Excel

По словесным описаниям построена гипотеза: **балл = стадия + темп роста**.

| Стадия | Балл | Темп роста | Балл |
|---|---:|---|---:|
| Исследование | 1 | Стабилен | 1 |
| Прототип / PoC | 2 | Растёт | 2 |
| Пилот | 3 | Растёт быстро | 3 |
| Раннее внедрение | 4 | | |

Если в описании несколько стадий, при кодировании взята наиболее поздняя явно указанная. Например: пилот 3 + быстрый рост 3 = 6.

Формула совпала в **97 из 100 строк**. Расхождения:

| Номер | Балл Excel | По гипотезе |
|---|---:|---:|
| 66 | 5 | 7 |
| 69 | 5 | 7 |
| 93 | 4 | 6 |

Это **гипотеза, не подтверждённая авторами формула**. Исходные баллы не исправлены. Их среднее — 5,22; значения лежат от 3 до 7.

Высокий балл не означает «вероятность слабого сигнала». Например, более поздняя стадия увеличивает балл, хотя технология одновременно приближается к зрелости. Поэтому баллы сохранены для объяснения известных технологий, но не подставлены в классификатор вместо текста. Для нового материала балл Excel не выдумывается.

## 7. PostgreSQL: куда нажимать

Данные уже включены в SQL. Отдельный импорт CSV и настройка путей на сервере не нужны.

1. Открой **pgAdmin 4**. Слева разверни **Servers → свой PostgreSQL → Databases**. При подключении используй пароль, заданный при установке PostgreSQL.
2. Нажми правой кнопкой на базу **postgres → Query Tool**.
3. Открой `SQL/01_Создать_базу.sql` через значок папки / Open File. Убедись, что включён **Auto-commit**, и нажми **Execute Script / F5**. Эта команда создаёт `technology_signals`. Если такая база уже есть, первый файл пропусти.
4. Нажми правой кнопкой **Databases → Refresh**. У новой базы **technology_signals** открой собственный **Query Tool**. Проверь, что в заголовке выбрана именно она.
5. Открой `SQL/02_Загрузить_данные.sql` и выполни целиком. В результате должны появиться количества **100, 7299, 248, 19**. Загрузка выполняется одной транзакцией и при повторном запуске не добавляет второй экземпляр данных.
6. Открой `SQL/03_Проверить_данные.sql`. Выделяй **один SELECT до точки с запятой**, нажимай **F5** и смотри вкладку **Data Output**. Ожидаемые результаты подписаны над запросами. Пустая выдача проверки дублей означает, что таких дублей нет.
7. Таблицы находятся слева: **technology_signals → Schemas → signals → Tables**. При необходимости нажми **Refresh**.

| Таблица | Содержимое |
|---|---|
| `signals.reference_signals` | 100 сигналов, исходные описания, баллы и отдельно их предполагаемые составляющие |
| `signals.publications` | Все 7299 исходных записей ленты |
| `signals.training_examples` | 248 подготовленных примеров с происхождением разметки и делением на обучение/проверку |
| `signals.source_catalog` | 19 источников из справочника |

Поля исходных таблиц сохранены текстом: так можно проверить пропуски и форматы до преобразования типов. В запросах с баллами `::integer` означает «читать это значение как целое число». `NULL` означает отсутствие значения; это не ноль.

SQL проверен разборщиком синтаксиса PostgreSQL, а включённые данные сверены с исходными таблицами. **На работающем сервере PostgreSQL эти файлы в данной сборке не запускались.** Сами расчёты и ожидаемые результаты независимо пересчитаны на данных.

## 9. Что получает разработчик

Готовый файл `Модель.pkl` содержит и словарь, и классификатор. Для применения достаточно:

```python
import pickle

with open("Модель.pkl", "rb") as файл:
    модель = pickle.load(файл)

класс = модель.predict([текст_статьи])[0]
оценки = модель.predict_proba([текст_статьи])[0]
```

`текст_статьи` — обычная строка с очищенным английским текстом содержательной публикации. Пустые страницы, поисковый вопрос, только заголовок, HTML и русские тексты не следует подавать как проверенные входы. Порядок оценок соответствует `модель.classes_`: нельзя считать, что слабый сигнал всегда находится в одном и том же номере столбца.

Путь материала в будущем приложении: **вопрос пользователя → поиск публикаций по теме → получение текста → модель → объединение материалов об одной технологии → ранжирование**. Шесть направлений служат темами поиска; целевые классы модели — три статуса из начала документа.

Для списка оставляются ответы «слабый сигнал», затем по одной позиции на технологию, в порядке оценки модели. Если подходящих технологий меньше 15, возвращается фактическое количество: подмешивать шум ради длины списка нельзя. Группы контрольной выборки нельзя автоматически переносить на неизвестные технологии.

Ссылки, подтверждение фактов и доверие к источнику хранятся отдельно от оценки модели. В соответствии с предоставленным справочником, для материала низкого доверия требуется независимое подтверждение либо явная отметка о пониженной доверенности. Наличие двух перепечаток одной новости само по себе независимого подтверждения не создаёт. Проверка этих фактов не подменяется числом из `predict_proba`.

**Обучение закончено; файл модели готов к загрузке в код.** Он решает описанную задачу классификации с приведённой проверкой и границами применения.
