# Слабые сигналы — сервис анализа зарождающихся технологических трендов

Кейс 11 хакатона «Лидеры цифровой трансформации» 2026, задача от Газпромбанк Тех:
автоматизированный сбор и анализ зарождающихся технологических трендов
(«слабых сигналов») по открытому запросу пользователя.

Пользователь вводит технологическое направление в свободной форме («квантовые
сенсоры», «нейроморфные чипы») — сервис ищет по открытым русскоязычным и
зарубежным источникам (научные публикации и препринты, гранты, аналитические
отчёты, отраслевые медиа, код), классифицирует найденное обученной ML-моделью и
формирует ТОП-15 зарождающихся трендов: описание, критерии слабого сигнала с
фактами из текста, кейс-примеры, подтверждения из независимых источников,
оценки аналитиков и объяснение, почему это слабый сигнал, а не зрелая
технология или шум.

## Архитектура

| Сервис | Что делает | Порт |
|---|---|---|
| `frontend` | React-интерфейс (поиск, результаты, карточка сигнала) | 5174 |
| `backend` | FastAPI: live-поиск, модель отбора, подтверждения, LLM-обогащение, API | 9000 |
| `collector` | Фоновый сбор из RSS/HTML/API-источников каждые 30 минут | — |
| `db` | PostgreSQL — общая БД для collector и backend | 5432 (только localhost) |
| `ollama` | Локальная LLM (qwen2.5:3b) — запасная модель, если GigaChat недоступен | 11434 |

Все пять сервисов — независимые Docker-образы, поднимаются одним
`docker-compose.yml` из корня репозитория. `backend` и `collector` пишут в
одну Postgres-базу, но определяют свои ORM-модели независимо (без
кросс-импорта между сервисами).

Модель отбора — v2 (`backend/app/models/v2/`, комплект аналитика):
мультиязычный энкодер E5 (`intfloat/multilingual-e5-small`, локально) сравнивает
смысл запроса и статьи, обученный классификатор определяет стадию технологии.
На отложенной выборке из 96 публикаций: accuracy 0.875, macro-F1 0.847,
precision класса «слабый сигнал» 0.929 — методология и метрики по классам в
[`Модель_и_методология/v2/Методология_v2.md`](Модель_и_методология/v2/Методология_v2.md),
пайплайн — в [docs/PIPELINE.md](docs/PIPELINE.md). Энкодер (~135 МБ) не хранится в git:
Docker скачивает его при сборке образа, для запуска без Docker —
`cd backend && python -m app.models.v2.download_encoder`.
Прежняя модель v1 (`backend/app/models/signal_classifier.pkl`, TF-IDF →
LogisticRegression, включается `MODEL_VERSION=v1`) и методология её обучения — в
`Модель_и_методология/v1/Методология_и_инструкция.md`
(94.7% точность на 76 контрольных публикациях, 100% совпадение
реконструированного ТОП-15 с оригинальными данными).

Языковые модели (облачные — через API, модель каждого ответа показывается в
интерфейсе и пишется в лог):

| Задача | Модель |
|---|---|
| Отбор и ранжирование сигналов | локальные: E5 + классификатор (без LLM) |
| Описания сигналов, критерии, резюме источников, оценки отчётов, перевод запроса | GigaChat 2 Max |
| Итоговый вывод по ТОП-15 | GigaChat-3-Ultra (согласовано) |
| Запасная модель при недоступности GigaChat | qwen2.5:3b (Ollama, локально) |

## Требования

- Docker + Docker Compose
- ~6 ГБ свободного диска (веса qwen2.5:3b — ~1.9 ГБ, энкодер E5 — ~135 МБ,
  образы сервисов)
- Доступ в интернет: Hugging Face (энкодер при сборке), GigaChat
  (`ngw.devices.sberbank.ru`, `api.giga.chat`), OpenAlex и другие источники
- Порты 5174, 9000, 11434, 5432 (только localhost) свободны на хосте

Ключи GigaChat и OpenAlex уже заданы значениями по умолчанию в
`docker-compose.yml`, корневой сертификат НУЦ Минцифры для GigaChat лежит в
`certs/` — дополнительно ничего настраивать не нужно.

## Быстрый старт

```bash
git clone <URL этого репозитория>
cd <папка репозитория>
docker compose up -d --build
```

Первый запуск дольше обычного: сборка backend скачивает энкодер E5, Ollama
скачивает веса запасной модели (~1.9 ГБ), backend ждёт готовности БД. Через
несколько минут:

- Веб-интерфейс: http://localhost:5174
- API backend: http://localhost:9000 (`GET /health` — проверка живости)

Проверить статус контейнеров: `docker compose ps` — все сервисы должны быть
`Up`, `db` — `Up (healthy)`.

## Переменные окружения (необязательные)

Всё работает и без них. Задаются в `.env` в корне репозитория или перед
`docker compose up`:

| Переменная | Зачем |
|---|---|
| `GIGACHAT_AUTH_KEY` | Свой ключ GigaChat вместо ключа по умолчанию |
| `OPENALEX_API_KEY` | Свой ключ OpenAlex (без ключа — ~2 поиска в сутки на IP) |
| `GITHUB_TOKEN` | GitHub API: без токена 60 запросов/час на IP, с токеном — 5000/час |
| `SEMANTIC_SCHOLAR_API_KEY` | Semantic Scholar: безключевой пул может быть перегружен (429) |
| `CONTACT_EMAIL` | Контактный email для polite pool arXiv/Crossref/OpenAlex |
| `ENRICHMENT_PROVIDER` | `ollama` — генерировать описания через локальную qwen вместо GigaChat |
| `MODEL_VERSION` | `v1` — включить прежнюю модель TF-IDF вместо v2 |
| `RELEVANCE_THRESHOLD` | Порог смысловой близости запроса и статьи (по умолчанию 0.79) |
| `LOG_DRIVER` | `journald` на Linux-сервере с systemd (по умолчанию `json-file`) |

```bash
GITHUB_TOKEN=ghp_xxx docker compose up -d --build
```

## Проверка сценария

1. Открыть http://localhost:5174
2. Ввести технологическое направление, например `Микрофлюидные технологии`
   (поиск занимает 1–5 минут; повторный запрос быстрее за счёт кэша)
3. Дождаться прогресса (сбор → скоринг → ранжирование)
4. На странице результатов — счётчики источников и кандидатов, «Итоги поиска»
   (вывод по ТОП-15), ТОП-15 сигналов с оценкой модели и ключевыми предикторами,
   вкладка «Исключённые» с причиной исключения
5. «Отчёт» сигнала — описание, проблема, преимущество, критерии слабого сигнала
   с фактами из текста, где технология уже проявилась, фрагмент источника,
   оценки аналитиков со сводной оценкой, источники и подтверждения (дата, тип,
   язык, уровень доверенности, русское резюме зарубежных материалов)
6. «История запросов» в шапке — прошлые поиски этого браузера

## Деплой на сервер (публичный доступ)

По умолчанию все порты (`5174`/`9000`/`11434`/`5432`) привязаны к `127.0.0.1` —
доступны только с той же машины. Для публичного доступа нужен reverse-proxy
перед контейнерами; Для автоматизации деплоя на сервер (Ubuntu) создан скрипт — в [`deploy/`](deploy/):

```bash
sudo bash deploy/setup-server.sh
```

Ставит nginx (единая точка входа: `/` → frontend, `/api/` → backend),
настраивает ufw, поднимает стек через `docker compose`, включает HTTPS через
certbot (если DNS домена/`sslip.io`-адреса уже указывает на сервер). 
Домен задаётся в `deploy/nginx/signals.conf` и в `deploy/setup-server.sh`
(переменная `DOMAIN`); фронтенду нужен `.env` с `VITE_API_BASE_URL=/api`
(шаблон — [`.env.production.example`](.env.production.example), в нём же
`LOG_DRIVER=journald`). Логи backend дополнительно пишутся в `logs/backend/`.

## Остановка работы сервиса

```bash
docker compose down        # остановить, данные (БД, веса Ollama) сохраняются в volume
docker compose down -v     # остановить и стереть ВСЕ данные
```

```
backend/                  FastAPI: API, пайплайн классификации и LLM-обогащения
RSS-collector/            фоновый сбор из RSS/HTML/API-источников
frontend/                 React + TypeScript + Tailwind интерфейс
Модель_и_методология/     v1/ и v2/: обученные модели, ноутбуки обучения, методология, метрики

docker-compose.yml        оркестрация всех сервисов
.env.production.example   шаблон переменных окружения для деплоя
```
