## 2. Суть задачи — два этапа

### Этап 1. Обучение модели на закрытом датасете
- Организаторы дают датасет с размеченными слабыми сигналами (ground truth скрыт)
- Требование: точность классификации **≥75–80%** (Precision / Recall / F1)
- **Обязательна интерпретируемость** — система должна показывать, по каким признакам
  наблюдение отнесено к слабому сигналу

### Этап 2. Поисково-аналитический модуль по открытому запросу
- Пользователь вводит свободный запрос («технологии в ИИ», «слабые сигналы в кибербезопасности»)
- Система ищет по открытым источникам в реальном времени, **не ограничиваясь датасетом**
- Выдаёт **ТОП-15** зарождающихся трендов
- Для каждого: описание технологии, потенциальное преимущество, кейс-пример,
  источник(и), скоринг/уверенность модели, объяснение отнесения к зарождающемуся тренду
- **Жёстко:** зрелые технологии со сформированным рынком, выраженными лидерами
  и устойчивым конкурентным разделением в выдачу попадать не должны
- Вся аналитическая выдача и интерфейс — **на русском языке**

## 5. Моя зона ответственности (бэкенд)

1. **Схема PostgreSQL** — сырые данные источников + результаты анализа
2. **API-слой на FastAPI**
   - `POST /search` — открытый запрос → пайплайн → ТОП-15
   - `GET /insight/{id}` — страница-отчёт по сигналу
   - Счётчики (бонусные пункты ТЗ): обработано источников, кандидатов найдено,
     сигналов с уверенностью >75%
3. **Оркестрация пайплайна (инфраструктура, не логика)** — строю скелет
   последовательности парсинг → NLP → скоринг → фильтрация мейнстрима →
   ранжирование как pluggable-этапы: асинхронно, с очередью или стримингом
   статуса. Сама модель/веса/пороги/критерии "зрелый vs зарождающийся" —
   не моя часть (см. разделение ниже)
4. **Отказоустойчивость парсеров** — отдельный критерий оценки 8.2
5. **Docker, README, CI/CD через SourceCraft**

### Разделение с дата/бизнес-аналитиком (в команде — одна роль на двоих)

- **Я (бэкенд) — фундамент/инфраструктура:** БД, API, оркестрация шагов

- **Аналитик — содержание:** сама NLP-модель, скоринг, критерии фильтрации

## 6. Что уже сделано

### 6.1 Таблица доверенных источников
Файл `Источники_рабочая_таблица.md` / `.xlsx` — 19 источников с полями:
источник, ссылка, темы, тип, доверие, интерфейс, ключ, язык, ограничения.

**Уровни доверия** (поле `trust_level`):
- `high` — первоисточник, самодостаточен
- `medium` — официальный, но вторичный или со смещением
- `low` / ⚑ — по ТЗ **не может быть единственным основанием** для ТОП-15,
  нужно кросс-подтверждение

**Три слоя сбора:**

| Слой | Источники | Что ловит |
|---|---|---|
| API | arXiv, Crossref, OpenAlex, USPTO ODP, EPO OPS, Semantic Scholar, OECD, Роспатент | Научно-патентные сигналы: стадия «Исследование/Прототип», рост публикаций, новые заявители, CPC-классы |
| RSS | TechCrunch, SiliconANGLE, MIT News, McKinsey, ВШЭ | Венчурно-рыночные: раунды, выходы из стелса, первые контракты — **большинство позиций ТОП-15** |
| HTML | Stanford HAI, МФТИ, A3/Automate, FS-ISAC, BCG | Остаток, самые хрупкие парсеры |

**Не использовать в автосборе:** WIPO/PATENTSCOPE (Terms запрещают scraping),
Crunchbase (лицензированный API), SSRN (TDM ограничен), ACM DL (по подписке,
обходить через Crossref по DOI), Google Patents (не первоисточник, нет REST API).

**Известный пробел:** нет государственных реестров, хотя ТЗ их прямо перечисляет.
Стоит добавить SEC EDGAR (открытый API, финтех), NIST/ISO (стандарты).

**Второй пробел:** признак «зрелый тренд — исключить» по текущим источникам
считается плохо. Отдельного сигнала для фильтрации мейнстрима пока нет.

### 6.2 Seed-лист компаний
`seed_companies.csv` / `.md` — **254 компании**, извлечены из колонки «Компании»
датасета 100 сигналов, сгруппированы по 6 областям (Финтех 47, Защита ИИ 46,
Инд.ИИ 46, Edge 41, Роботы 39, ИИ-инфра 35).

Колонки: `company, areas, domain, feed_url, status`. Домены пустые — заполняет резолвер.

**Назначение — верификация, не discovery.** Эти компании уже найдены. Польза:
подтверждение медиа-новостей официальным анонсом компании (требование ТЗ
о кросс-подтверждении), проверка качества открытого поиска без ground truth,
готовая разметка для обучения.

### 6.3 RSS-коллектор (работает)
Каталог `RSS-collector/`, запущен в Docker, копит данные.

```
collector/
  feeds.py      реестр лент + метаданные доверия (dataclass Feed)
  db.py         SQLAlchemy-модели Source и FeedItem
  discover.py   автодискавери лент (link rel=alternate + типовые пути)
  core.py       сбор, ретраи, дедупликация
  main.py       CLI: init | discover | collect | loop | stats
```

Стек: feedparser, httpx, SQLAlchemy 2.0, psycopg3, selectolax.
Compose: postgres:16-alpine + adminer (8080) + collector (loop 30 мин).

**Активные ленты (6):** techcrunch, siliconangle, mit_news, mckinsey,
hse_science, hse_expertise. Состояние на 16.09: 190 записей, 0 сбоев.

**Заложенные решения:**
- Изоляция лент — падение одной не роняет прогон
- Ретраи с экспоненциальной задержкой на 429/5xx, учёт `Retry-After`
- Условный GET по `ETag` / `Last-Modified`
- Дедупликация через `UNIQUE(url_hash)` на уровне БД, не в памяти
- `consecutive_failures` и `last_error` на источнике
- Полный текст статей **не сохраняется нигде** — у TechCrunch отдельные RSS Terms
  (атрибуция, ссылка на оригинал, контент не изменять)

**Схема БД:**

```
sources:     id, key, name, feed_url, site_url, source_type, trust_level,
             language, topics, is_indicator_only, sponsored_possible,
             attribution_required, notes,
             etag, last_modified, last_polled_at, last_ok_at,
             consecutive_failures, last_error

feed_items:  id, source_id FK, url, url_hash UNIQUE, title, summary, author,
             published_at, raw_categories, retrieved_at,
             + денормализация: trust_level, source_type, language,
               is_indicator_only, sponsored, is_translated
```

Денормализация — чтобы выдача строилась одним запросом: ТЗ требует показывать
уровень доверенности рядом с каждым источником.

**Важно про историю:** RSS отдаёт только последние 20–50 записей.
У TechCrunch глубина ленты меньше суток — при простое контейнера данные теряются
безвозвратно. Коллектор должен опрашиваться не реже чем раз в 2–4 часа.
Прирост ~40–70 записей/сутки со всех лент.

## 7. Открытые вопросы

1. **Признак «тренд упоминаний»** — 2 недели накопленной RSS-истории мало.
   В датасете тренд оценивается на горизонте 12–24 месяцев. Два пути:
   архивная догрузка через sitemap/пагинацию (тот случай, где HTML-скрапинг
   реально нужен) либо считать тренд на лету через arXiv/OpenAlex/USPTO,
   где есть исторический поиск по датам. **Второй путь надёжнее.**
2. **Фильтрация мейнстрима** — как формально отличить зрелый тренд.
   Отдельного сигнала пока нет, а это критерий оценки 8.3.
3. **Время ответа на демо** — вопрос отправлен на Q&A-сессию: сколько источников
   реалистично обработать за запрос, какая latency приемлема, допустим ли
   частичный результат. От ответа зависит, нужна ли очередь задач.
4. **Интерпретируемость** — ожидается ли формальный feature importance (SHAP)
   или достаточно текстового объяснения от LLM поверх результатов модели.
